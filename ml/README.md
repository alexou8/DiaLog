# DiaLog ML -- Offline Research Pipeline

This directory is the **offline research / model-development pipeline** for
DiaLog. It is a standalone Python project used to prototype and honestly
evaluate statistical/ML methods (e.g. "does recent carb intake plus
medication timing predict a glucose spike?") before anyone decides whether
those methods are worth reimplementing in the production TypeScript
analytics engine at the repository root.

**This code is NOT deployed.** It does not run in the DiaLog product, is not
imported by the Next.js app, and its models are not served to users. Nothing
here has been clinically validated. See `docs/ML_PIPELINE.md` (repo root)
for the full methodology writeup, the leakage issues that were found and
fixed here, and the honest baseline-relative results.

## Layout

- `src/` -- library code: feature engineering (`features.py`), the
  chronological-split training/evaluation pipeline (`modeling.py`), a
  small model abstraction layer (`models/`), data loading/validation
  (`data/`), reporting (`reports.py`), and shared utilities (`utils/`).
- `scripts/` -- CLI entry points: ingest a CSV, build features, train,
  tune hyperparameters, generate a weekly report, and export findings.
- `examples/` -- runnable examples, including synthetic sample-data
  generation.
- `data/` -- sample/processed datasets. `sample_glucose_data.csv` is
  **synthetic**, generated by `examples/generate_sample_data.py`; any
  metric computed from it carries no clinical validity (see
  `data_provenance` in `scripts/export_findings.py` output).
- `models/`, `outputs/` -- gitignored artifact directories for trained
  models and generated reports.
- `tests/` -- pytest suite (unit, integration, and Hypothesis
  property-based tests), including tests that assert the anti-leakage
  properties of the pipeline (chronological split ordering, fold-only
  imputation, baseline metrics present in every report).

## Setup

```bash
cd ml
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Running the pipeline

```bash
# 1. Initialize the local sqlite event store
python scripts/init_db.py

# 2. (optional) generate synthetic sample data, then ingest it
python examples/generate_sample_data.py
python scripts/ingest_csv.py data/sample_logs.csv

# 3. Build the feature/training-example dataset (thresholds are configurable)
python scripts/preprocess_data.py --spike-threshold 200.0 --lookback-hours 6.0

# 4. Train + honestly evaluate the spike classifier (chronological split,
#    baseline comparisons, bootstrap CIs -- see docs/ML_PIPELINE.md)
python scripts/train_model.py --data-provenance "SYNTHETIC sample data -- no clinical validity"

# 5. Hyperparameter search using TimeSeriesSplit (never KFold/shuffled CV)
python scripts/tune_hyperparams.py

# 6. Export a full findings report (metrics, baselines, feature
#    importances, sample sizes, provenance) for a human reviewer deciding
#    whether a method is worth porting to the production TS engine
python scripts/export_findings.py --data-provenance "SYNTHETIC sample data -- no clinical validity"
```

## Running the tests

```bash
cd ml
source .venv/bin/activate
python -m pytest
```

## Why this matters: methodology discipline

Because this pipeline exists to inform decisions about production code, its
numbers have to be trustworthy, not merely good-looking. Concretely, this
means:

- **Chronological splits only.** Train on the earliest data, evaluate on
  later data (`src/modeling.chronological_split`), and use
  `sklearn.model_selection.TimeSeriesSplit` for cross-validation and
  hyperparameter tuning -- never a random/shuffled split or `KFold` on this
  time series.
- **No future information in features.** Every feature is computed from
  events at or before its anchor timestamp.
- **Imputation fit on the training fold only.** Median/most-frequent
  imputation happens inside the model pipeline's `.fit()`, not on the whole
  dataset beforehand.
- **Baselines on everything.** Every reported metric is compared against a
  majority-class baseline, a prevalence baseline, and a previous-reading
  persistence baseline, with the model's lift reported explicitly.
- **Uncertainty, not point estimates.** Bootstrap confidence intervals and
  sample sizes accompany every headline number.
- **Provenance is not optional.** `data_provenance` is a required field on
  every evaluation report and export; synthetic-data results are labeled as
  such in the machine-readable output, not just in prose.

See `docs/ML_PIPELINE.md` for the full narrative and honest results.
